# 사용 가이드

어댑터는 **학습 때와 같은 입력 형식** 으로 써야 결과표의 성능이 나옵니다. 이 문서는 그 형식을 정리합니다.
실행 예제는 [`examples/infer.py`](../examples/infer.py) 에 있습니다.

---

## 1. 어댑터 고르기

| 어댑터 | 원본 모델 |
|---|---|
| `adapters/E2B/<과제>` | `google/gemma-4-E2B-it` |
| `adapters/E4B/<과제>` | `google/gemma-4-E4B-it` |

- 과제마다 어댑터가 따로 있습니다. 과제에 맞는 어댑터와 프롬프트 틀을 함께 쓰세요.
- 어댑터는 **학습한 원본 모델에만** 붙습니다. E2B 어댑터를 E4B 나 다른 모델에 붙이면 안 됩니다.
- `adapter_config.json` 의 `base_model_name_or_path` · `revision` 이 학습에 쓴 원본 모델입니다.
- 설정: LoRA r=16 · α=32 · dropout 0.05 · 대상 층 `model.language_model.layers.N.self_attn.{q,k,v,o}_proj`.
- **실사용 권장은 `topic` · `terms` · `summary`** 입니다. `followup` 은 원본보다 못하고 `answer` 는 원본과 차이가 없습니다 (README 표).

---

## 2. 메시지 구성

- **사용자 메시지 1개만** 보냅니다. 시스템 메시지는 쓰지 않습니다.
- 원본 모델의 채팅 템플릿을 `add_generation_prompt=True` 로 적용합니다. 생각(thinking) 모드는 켜지 않습니다.
- 사용자 메시지 = 과제 프롬프트 틀(`prompts/<과제>.txt`, 끝 줄바꿈 제거)의 `{자리표시자}` 를 입력값으로 바꾼 것.
- 분류 과제에도 **라벨 목록을 프롬프트에 넣지 않습니다.** 어댑터가 라벨을 이미 배웠습니다.

---

## 3. 과제별 프롬프트 틀

| 과제 | 틀 | 자리표시자 |
|---|---|---|
| 주제분류 | `prompts/topic.txt` | `{question}` = 고객 문의 |
| 상황분류 | `prompts/situation.txt` | `{question}` = 고객 문의 |
| 용어추출 | `prompts/terms.txt` | `{question}` = 고객 문의 |
| 요약 | `prompts/summary.txt` | `{transcript}` = 상담 전문 |
| 후속질문 | `prompts/followup.txt` | `{question}` = 고객 문의 · `{answer}` = 상담원 답변 |
| 답변생성 | `prompts/answer.txt` | `{question}` = 고객 문의 |

**상담 전문(`{transcript}`) 형식**

- 한 줄에 발화 1개 · 상담사 발화는 `TX `, 고객 발화는 `RX ` 로 시작합니다 (원 데이터 형식 그대로).
- 학습 최대 길이는 8,192 토큰(입력 + 출력)입니다.

**가림 표시**

- 학습 데이터의 가려진 값은 문맥에 따라 `[금액]` (금액) · `[숫자]` (날짜·시간 앞 숫자) · `[마스킹]` (그 밖) 으로 바뀌어 있습니다.

**예 — 주제분류 사용자 메시지** (설명용으로 만든 문의입니다)

```
다음 고객 문의의 상담 주제를 분류하시오.

문의: 해외여행 가기 전에 달러로 바꾸려면 어떻게 해야 하나요?
```

**예 — 요약 사용자 메시지**

```
다음 상담 전문을 요약하시오. 고객이 문의한 내용과 상담원이 안내한 내용을 모두 포함하시오.

전문:
TX 안녕하세요, 고객센터입니다.
RX 네, 자동이체 출금일을 바꾸고 싶어서요.
TX 네, 본인 확인 후 변경 도와드리겠습니다.
```

## 4. 생성 설정

결과표의 모든 수치는 아래 조건에서 냈습니다.

- **greedy** (샘플링 없음 · temperature 0).
- 정지 토큰 = 원본 모델 `generation_config` 의 eos ∪ 토크나이저 eos ∪ 턴 종료 토큰 `<turn|>`.
- **반복 페널티는 쓰지 않았습니다.**

| 과제 | 학습본 실제 출력 (평가 100~2,000건) | 학습 정답 최장 | 권장 생성 상한 |
|---|---|---|---|
| 분류 3과제 | 라벨 이름 1개 | — | 32 토큰 |
| 후속질문 | 평균 약 50자 | 263 토큰 | 384 토큰 |
| 요약 | 평균 약 155자 | 279 토큰 | 512 토큰 |
| 답변생성 | 평균 약 165자 | 784 토큰 | 1,024 토큰 |

- 권장 상한은 학습 정답의 최장을 덮는 값입니다.
- **상한에 닿아 정지 토큰 없이 끝난 답은 반복 루프로 보고 버리거나 다시 시도** 하세요. 답변생성 E2B 에서 100건 중 1건 끝나지 않는 반복이 나왔습니다.

---

## 5. 출력 처리

| 과제 | 출력 형식 | 처리 |
|---|---|---|
| 분류 3과제 | 라벨 이름 1개 | `labels/<과제>.labels.txt` 와 정확히 비교 |
| 요약 · 후속질문 · 답변생성 | 문장 (따옴표·화자 표시 없음) | 그대로 사용 · 상한에 닿으면 버림 |

라벨: `topic` 10종 · `situation` 3종 (민원응대 · 업무처리 · 일반문의) · `terms` 269종.

---

## 6. 주의점

1. **답변생성은 조회 결과·금리·기간·서류를 단정하거나 지어냅니다.** 학습 정답이 실제 계좌 조회를 전제로 한 답이 많기 때문입니다. 고객에게 바로 내보내지 마세요.
2. **후속질문은 원본보다 못합니다.** 답변에서 이미 안내한 내용을 다시 묻는 질문을 자주 만듭니다.
3. **상황분류는 질문 한 문장만 봅니다.** 평가셋의 69% 가 '업무처리' 라 정확도(약 70%)는 높아 보이지만, 소수 클래스 '민원응대' 를 잘 찾지 못합니다.
4. **용어추출은 정답을 1개만 인정하는 라벨로 학습했습니다.** '대출 · 대출연장 · 만기연장' 처럼 겹치는 용어를 혼동합니다.
5. **요약은 가려진 값을 드물게 지어냅니다** (100건 중 0~1건). 실제 값이 들어간 전문으로는 확인하지 않았습니다.

---

## 7. 서빙 (vLLM 등)

- 학습·평가는 **transformers + PEFT** 로만 했습니다. vLLM 등 서빙 엔진에서는 확인하지 않았습니다.
- 서빙 엔진의 LoRA 기능으로 원본 모델 1개에 어댑터 여러 개를 붙여 쓸 수 있으면, 위 형식 그대로 요청하면 됩니다. 쓰기 전에 같은 입력 몇십 건을 transformers + PEFT(`examples/infer.py`)와 서빙 엔진에 greedy 로 보내 출력이 같은지 확인하세요. 어댑터가 붙지 않으면 원본 성능(예: 주제분류 E2B 51.8%)이 나옵니다.
